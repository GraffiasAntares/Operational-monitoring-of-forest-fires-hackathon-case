# Backend MVP

## Первый этап: очаги FIRMS

`GET /api/v1/hotspots` запрашивает одновременно VIIRS S-NPP и NOAA-20 через
FIRMS Area API, приводит CSV к общему формату, удаляет точные дубликаты и
возвращает GeoJSON.

Перед запуском скопируйте `.env.example` в `.env` и вставьте полученный у NASA
ключ. Приложение автоматически читает локальный `.env`; переменная окружения
имеет приоритет над значением из файла.

```powershell
python -m uvicorn backend.app.main:app --reload
```

Пример запроса:

```text
GET http://127.0.0.1:8000/api/v1/hotspots?bbox=92.5,55.8,93.2,56.4&days=1
```

`bbox` передаётся как `west,south,east,north`. Для исторических данных можно
передать `start_date=YYYY-MM-DD`; текущий первый этап использует NRT-источники.

## Второй этап: пожарные события

`GET /api/v1/fire-events` сначала получает те же FIRMS-hotspots, затем HDBSCAN
объединяет соседние точки в пространстве и времени. В ответе GeoJSON-точка
события содержит число очагов, время первого/последнего наблюдения, bbox,
максимальный FRP и источники.

```text
GET http://127.0.0.1:8000/api/v1/fire-events?bbox=92.5,55.8,93.2,56.4&days=1
```

## Третий этап: гарь Copernicus Global Burnt Area

`GET /api/v1/burned-areas` получает ежедневную маску гари Copernicus Global
Burnt Area V4 (300 м) для переданного участка, объединяет соседние горелые
пиксели в GeoJSON-контуры и возвращает их примерную площадь в гектарах. Это
слой подтверждённой гари, а не оперативная детекция активного огня.

Для этого этапа добавьте в `.env` OAuth-данные клиента Copernicus Data Space:

```text
COPERNICUS_CLIENT_ID=...
COPERNICUS_CLIENT_SECRET=...
```

Пример запроса:

```text
GET http://127.0.0.1:8000/api/v1/burned-areas?bbox=92.5,55.8,93.2,56.4&date=2026-09-17
```

У слоя разрешение 300 м: его контуры и площади подходят для быстрого MVP и
fallback-режима, но не являются точной границей пожара. Для современного
продукта поддерживаются даты с 2025-01-01.

## Четвёртый этап: тяжесть dNBR

`GET /api/v1/severity/dnbr?bbox=...&before_date=...&after_date=...` получает
Sentinel-2 L2A B08/B12 для двух временных окон, рассчитывает `NBR_before -
NBR_after` на 20 м и отдаёт классы `low`, `moderate` и `high` в GeoJSON.

## Пятый этап: лесной ущерб

`GET /api/v1/forest-impact?bbox=...&date=...` накладывает подтверждённую
гарь Copernicus на публичные COG ESA WorldCover 2021 v200. Для каждого
контура добавляется `forest_burned_ha` для класса `Tree cover` (10).

## SAFE

`GET /api/v1/safe/status` сообщает доступность SAFE. У указанного репозитория
нет публично указанного checkpoint/STAMP; после получения совместимых весов
задайте `SAFE_MODEL_PATH`.

## Как заменить готовые части собственным ML в будущем

Текущий MVP намеренно построен на готовых продуктах и объяснимых алгоритмах.
Источники данных — FIRMS, Sentinel-2 и WorldCover — можно сохранить, заменяя
только конкретный вычислительный этап.

| Этап MVP | Что можно заменить | Что останется без изменений |
| --- | --- | --- |
| Очаги FIRMS | Детектор активного огня на спутниковых снимках | API и формат GeoJSON hotspots; FIRMS можно оставить как baseline и разметку для проверки |
| HDBSCAN-события | Модель трекинга пожара во времени или графовая модель объединения очагов | Поток FIRMS-точек и контракт `fire-events` |
| Copernicus Burnt Area 300 м | Сегментация гари на Sentinel-2 10–20 м, например дообученный SAFE/UNet | Контракт GeoJSON контуров, площадь и связь с событием |
| dNBR | Регрессия тяжести или сегментация классов повреждения по multi-temporal Sentinel-2 | Пары снимков до/после, фильтрация облаков и классы ответа `low`/`moderate`/`high` |
| ESA WorldCover | Собственная модель лесной маски либо классификация пород/типов растительности | Пересечение контура гари с маской и поле `forest_burned_ha` |

Практичный путь развития: сначала собирать результаты текущего пайплайна,
сохранять для каждого события входные снимки, готовую маску и ручную проверку.
Тогда готовые слои становятся baseline-разметкой, а свой ML можно подключать
параллельно и сравнивать по IoU для контуров, ошибке площади и качеству классов
тяжести. Не меняйте API-контракт при первой замене: фронтенд и остальные этапы
останутся совместимыми.

Запуск тестов:

```powershell
python -m pytest -q
```
